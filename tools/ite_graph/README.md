# ite_graph — граф доробок бази ITE

Аналог `odoo_graph` з репозиторію `todo_timur`: граф кастомного шару конкретної бази й автоматичний пошук
проблем, яких не видно ні в коді, ні в інтерфейсі окремо. Тут граф будується з таблиць конфігурації ITE.
**Не реалізовано:** потрібне читання БД стенду (Q-01).

## Що читатиме

| Шар | Таблиці | Ребра | Джерело |
|---|---|---|---|
| RRT-методи | `RRT`, `RRTK`, `RRSCT` | метод → об'єкт, → подія/джерело, → збірка користувача, → таблиці з коду `BL` | code, doc_id=109945, 112142 |
| Типи процесів | `DMT` (`KSTO`, `IT10`, `BL9`, види відображення `KREP_*`) | тип → ТГО, → вид відображення, → платформа 9/10 | forms, doc_id=124883 |
| Облік | `STO`, `STOT` | ТГО → статті → рахунки | README §3.2 |
| Меню й доступ | `MENU`, `MNU`, `ARMM`, `MELU`, `UST`, `USTZ` | пункт меню → параметр доступу | code, doc_id=108824 |
| Екрани | `SCRZ`, `SCRS` | екран → таблиця, → поле | libs, doc_id=124203 |
| Конфігурація | `CNFOBJ`, `CONFREQS` | об'єкт → пакет → комплект і статус | forms, doc_id=124389, 124395 |

Поля `RRT`/`RRTK`, `STO`/`STOT`, `SCRZ`/`SCRS` звірити через `ite_form_fields` або на стенді перед
реалізацією. Тільки читання, бізнес-дані не читаються.

## Які проблеми шукатиме

- дублі статей ТГО, що дають подвійні проводки (як схема 9545, статті 210 і 265 — claude, doc_id=137289);
- типи процесів без ТГО або ТГО без статей;
- RRT-методи з `_`, що посилаються на неіснуючі збірки або скасовані методи;
- збіги `_`-кодів між різними доробками;
- розбіжність поля `BL` у базі з файлом у `src/csharp/`.
